# CiteWeave v2：新概念、实验思路与阶段性结果

**用途：** 用相对简单的语言说明本轮新增机制、实验为什么这样设计，以及目前得到了什么结果。
**注意：** 当前 v2 结果属于真实探索性实验，不是最终论文结果。

---

## 1. 这次研究方向发生了什么变化？

上一轮实验发现：

- Graph RAG 相对无参考明显更好；
- 但相对扁平结构化证据没有优势；
- 相对纯视觉模型也没有优势。

这并不能证明图没有用。更可能的原因是，旧任务主要在问最大节点、最强边、节点数量和聚类归属等简单事实。这些问题看表格也能回答，不需要图计算。

因此，本轮工作的核心变化是：

> 不再研究“把图作为额外输入有没有用”，而是研究“在大图上执行结构计算，能不能解决普通 RAG 难以解决的复杂问题”。

人类审核也进行了类似升级：

> 不再研究“保存历史审核记录有没有用”，而是研究“能否把人类反馈编译成可迁移、可验证、可撤销的审核规则”。

建议的新论文主线是：

> **Human-Guided Graph Program RAG for Auditable Scientific Landscape Synthesis**

## 2. 本轮新增的关键概念

这里只解释本轮真正新增的复杂概念，不再介绍图、RAG 等基础概念。

### 2.1 图算子（Graph Operator）

图算子是在完整图上执行的一项标准计算。

| 图算子 | 解决的问题 |
|---|---|
| `shortest_path` | 两个研究主题通过哪些中间主题连接？ |
| `community_aggregate` | 哪个社区是网络核心，哪个社区较为边缘？ |
| `boundary_edge_filter` | 哪些节点或边连接了不同研究社区？ |
| `delete_node` | 删除某个核心节点后，网络是否仍然连通？ |
| `delete_edge_counterfactual` | 删除某条桥边后，原来的结构结论是否还成立？ |
| `threshold_sensitivity` | 改变建图阈值后，发现是否稳定？ |
| `temporal_shift` | 某个主题在早期和近期的结构位置发生了什么变化？ |
| `cross_layer_join` | 关键词、作者和机构网络是否支持同一结论？ |

图算子的意义是让系统真正计算结构，而不是让 LLM 在 prompt 中阅读几万条边并自行猜测。

### 2.2 图程序（Graph Program）

一个复杂研究问题通常不能由单个算子回答。图程序就是把多个图算子按顺序组合起来。

例如，要判断某个主题是不是稳定的跨领域桥梁，可以执行：

```text
识别社区
  → 找跨社区路径
  → 计算桥梁节点
  → 删除该节点重新计算
  → 改变建图阈值重新计算
  → 比较不同时间段
```

最后得到的不只是“它很重要”，而是类似下面的结论：

> 该主题连接了两个研究社区；删除后网络仍然连通，但替代路径明显变长；这一现象在多个阈值下仍然存在。因此它是重要但非唯一的桥梁。

### 2.3 Graph Program RAG

Graph Program RAG 将“检索”和“图计算”结合起来：

```text
问题分解
  → 在完整图上执行算子
  → 检索支持结果的节点、边和路径
  → 进行反事实与稳定性检查
  → 让模型解释计算结果
```

普通 RAG 主要解决“找到哪些资料”，Graph Program RAG 还解决“需要在关系网络上计算什么”。

### 2.4 反事实检查（Counterfactual Check）

反事实检查是主动改变一个条件，再观察原结论是否仍然成立，例如：

- 删除最重要的节点；
- 删除最强的跨社区边；
- 提高或降低建图阈值；
- 改变社区划分参数。

如果条件稍微改变，结论就消失，文章必须降低结论强度。如果多种条件下都成立，才能认为这是相对稳定的结构现象。

### 2.5 现象卡（PhenomenonCard）

现象卡是新的文章生成单位，用来替代“一张图配一段说明”。

每张现象卡包含：

```text
claim                    发现了什么
supporting_graph_program 使用了哪些图算子
evidence_paths           哪些节点和路径支持它
counterfactual_result    改变条件后是否仍然成立
alternative_explanation 是否存在其他解释
scope_and_limitation     这个结果不能说明什么
article_slots            应放入文章哪些章节
```

它的作用是把图结果从简单描述升级为经过检验的论证单元。

### 2.6 Provenance 回链

Provenance 回链记录一条文章结论是如何产生的：

```text
原始数据 → 图中的节点和边 → 图算子 → 派生事实 → claim → 文章段落
```

审核者可以沿着这条链重新检查结论，而不需要相信模型的自然语言解释。

### 2.7 Human Review Compiler

Human Review Compiler 把自然语言审核意见转换成系统可以执行和验证的规则。

例如，人类指出：

> 只有关键词增长证据时，不能写成“该技术驱动了领域发展”。

系统将其编译为：

```text
适用对象：含“驱动”“导致”等因果词的 claim
触发条件：证据只有频次、共现或网络位置
处理动作：降低表述强度，或者提交人审
验证要求：在新主题的相似句子上测试
安全要求：不能误改真正有因果证据的句子
```

### 2.8 审核依赖传播

如果某条上游证据或图算子被人类否定，系统自动找到所有受影响内容：

```text
source → evidence → operator → claim → paragraph
```

例如，一个图算子算错后，Results、Discussion 和 Conclusion 中使用该结果的段落都会进入重新审核，而不是只修改当前看到的一句话。

### 2.9 守卫规则、迁移验证与回归测试

审核规则不能无条件应用。它必须包含适用条件，也就是 guard。

一条规则要自动启用，还需要通过两类测试：

- **迁移验证：** 在未参与规则形成的新主题上，能否继续正确修复相似问题；
- **回归测试：** 修复一种错误时，是否破坏了原本正确的无关内容。

因此，系统学习的不是一句通用 prompt，而是一条有边界、有验证结果、可以撤销的规则。

## 3. Graph RAG 实验为什么要重新设计？

### 3.1 旧实验为什么测不到图优势？

旧实验存在两个根本问题。

第一，任务太简单。最大节点和最强边等问题不依赖复杂结构。

第二，`graph_rag` 和 `flat_structured` 含有几乎相同的事实。模型只要读到答案，不需要使用图的连接关系。

所以旧实验实际测量的是“有结构化证据是否优于没有证据”，没有真正测量“图计算是否优于普通文本或表格检索”。

### 3.2 新实验同时增加两个难度

新的基本假设是：图优势需要两个条件同时成立。

```text
更大的图 + 更复杂的问题
```

#### 图规模

| 规模 | 大致范围 | 实验作用 |
|---|---:|---|
| Small | 约 100 节点 | 作为简单负对照 |
| Medium | 约 300–1,000 节点 | 开始超出可靠的完整上下文阅读 |
| Large | 完整 canonical graph | 测试真实的全局结构计算 |

#### 任务复杂度

| 等级 | 任务 | 预期 |
|---|---|---|
| C1 | 单节点、单边事实 | 图不应明显领先 |
| C2 | 多跳路径、共同邻居 | 开始体现图优势 |
| C3 | 社区角色、跨社区桥梁 | 应出现较强优势 |
| C4 | 删点、删边和阈值扰动 | 应出现较强优势 |
| C5 | 跨网络、跨时间综合 | 最能体现 Graph Program 的价值 |

如果 Graph Program 在 C1 也大幅领先，反而可能说明实验条件没有控制好。C1 应作为机制负对照。

## 4. 各个实验对照到底在测什么？

这次不再只设置“有图”和“没图”，而是拆分不同能力来源。

| 实验条件 | 提供给模型的内容 | 主要回答的问题 |
|---|---|---|
| `no_reference` | 不提供外部证据 | 没有 grounding 时能否猜对？ |
| `flat_tfidf` / `flat_bm25` | 普通词法检索结果 | 图程序是否优于强文本检索？ |
| `graph_query_retrieval` | 根据问题实体检索连通子图 | 只做图检索是否足够？ |
| `graph_retrieval` | 保证含有答案证据的子图 | 证据已经找对时，模型能否完成推理？ |
| `operator_only` | 只提供图算子结果 | 答案能力有多少来自算子输出？ |
| `flat_program` | 与 Graph Program 完全相同的信息，但扁平展示 | 图的展示形式是否有独立贡献？ |
| `graph_program` | 连通证据、图算子和派生事实 | 完整方法的效果如何？ |
| `figure_vlm` | 只看可视图 | 视觉理解能否完成同样任务？ |

其中最重要的比较是：

1. `graph_program` vs. `flat_tfidf/BM25`：图计算是否优于普通文本 RAG；
2. `graph_program` vs. `graph_retrieval`：执行算子是否比只检索子图更好；
3. `graph_program` vs. `operator_only`：原始图和 provenance 是否有额外价值；
4. `graph_program` vs. `flat_program`：图的组织形式本身是否有贡献。

## 5. 当前 Graph Program 实验结果

> 以下均为真实 API pilot，但主题和样本量仍然较小，应当解释为阶段性发现。

### 5.1 复杂现象面板

在 5 个主题、24 个复杂问题上：

| 条件 | 准确率 |
|---|---:|
| Graph Program | 100.0% |
| 普通图检索 | 37.5% |
| TF-IDF 检索 | 12.5% |
| Flat Program | 100.0% |

复杂问题包括多跳连接、桥边删除反事实、社区角色对比、核心节点删除后的韧性和时间—结构变化。

阶段性解释：

- Graph Program 比普通词法检索高 **87.5 个百分点**；
- 比只提供相关图证据高 **62.5 个百分点**；
- 与信息完全相同的 Flat Program 打平。

### 5.2 BM25 强文本基线

| 条件 | 准确率 |
|---|---:|
| Graph Program | 100.0% |
| BM25 | 12.5% |

BM25 在多跳问题上偶尔能命中相关实体，但在社区、反事实、韧性和时间结构问题上几乎无法形成完整答案。

这说明仅仅检索名称相近的节点和边，不等于完成了结构计算。

### 5.3 图程序机制消融

| 条件 | 准确率 |
|---|---:|
| Graph Program | 100.0% |
| Operator Only | 79.2% |
| Oracle Graph Retrieval | 33.3% |
| Query Graph Retrieval | 25.0% |

这个结果带来三个发现：

1. 图算子承担了大部分答案能力。只给算子输出已经能达到 79.2%；
2. 仅仅检索到正确子图仍然不够，模型不一定能自行完成全局和反事实计算；
3. Graph Program 比 Operator Only 高 20.8 个百分点，说明原始图和证据路径可能仍有补充价值，但当前样本不足。

### 5.4 Graph Program 与 Flat Program 完全打平

这是本轮最重要的负结果：

| 条件 | 准确率 |
|---|---:|
| Graph Program | 100.0% |
| Flat Program | 100.0% |

两者拥有相同节点、边、算子结果和派生事实，只是展示形式不同。

因此目前不能声称“把证据组织成图格式会提高模型能力”。更可靠的说法是：

> 在完整图上执行正确的结构计算，再提供可追溯结果，可以解决普通检索难以解决的复杂问题。

创新点必须放在图程序、查询规划、反事实和 provenance 上，而不是图 JSON。

### 5.5 初步规模实验

| 图规模 | Graph Program 相对强基线 |
|---|---|
| Small | 基本打平 |
| Medium | 基本打平 |
| Large | 开始出现优势 |

这一方向符合研究假设，但每档样本非常少，不能据此证明“图越大，优势越明显”。

正式实验需要在每个规模上生成足够多的同构问题，并检验“方法 × 图规模 × 任务复杂度”的交互关系。

## 6. 文章实验是怎么重新设计的？

### 6.1 旧文章实验的问题

旧文章虽然结构完整、证据充分，但图通常只贡献一小段解释，导致：

- 图的作用在全文中很弱；
- 文章仍以数量、排名和简单趋势为主；
- Results 与 Discussion 缺少复杂结构现象；
- 图没有真正帮助形成科学论证。

### 6.2 新文章实验的基本思路

新系统先生成多张通过验证的现象卡，再用它们组织文章。

每篇文章至少需要：

- 1 张多跳或社区结构卡；
- 1 张反事实或稳健性卡；
- 1 张时间变化卡；
- 1 张跨图或跨证据综合卡。

图派生结论必须分布在 Results、Discussion、Limitations 和 Conclusion。这样才能检验图能力是否真正影响全文，而不是只生成一段图注。

### 6.3 第一篇多现象文章结果

已在 `digital_twins_healthcare_2012_2024` 主题上生成第一篇 v2 文章。

文章使用了 5 张现象卡：

1. 多跳连接；
2. 桥边删除反事实；
3. 社区角色对比；
4. 核心节点删除韧性；
5. 时间—结构变化。

确定性审计结果：

| 指标 | 结果 |
|---|---:|
| 文章长度 | 3,576 词 |
| 现象卡使用 | 5/5 |
| 正文代表文献 | 4 篇 |
| CARD 引用 | 59 次 |
| WORK 引用 | 17 次 |
| 可审计论证段落 | 26 段 |
| 合法 provenance 覆盖 | 24/26，92.3% |
| 结构与 provenance 检查 | 全部通过 |

### 6.4 与旧机器稿的初步比较

单主题盲化 LLM 预审结果：

| 维度 | 旧机器稿 | v2 文章 |
|---|---:|---:|
| 复杂现象 | 3/5 | 5/5 |
| 跨证据综合 | 3/5 | 5/5 |
| 图派生洞见 | 3/5 | 5/5 |
| 研究价值 | 3/5 | 5/5 |
| 领域具体性 | 3/5 | 4/5 |

新稿的主要进步是加入了反事实分析、结构机制、替代解释和明确局限。

但仍存在两个问题：

- `maturing field` 等表述超过了当前结构证据；
- 只连接了 4 篇代表文献，具体领域机制、应用和争议仍不够深入。

由于目前只有一个主题和一次 LLM 评审，不能声称新稿已经超过人类文章。

## 7. 人类审核实验为什么要重新设计？

### 7.1 旧审核数据的问题

| 项目 | 结果 |
|---|---:|
| 审核记录 | 32 条 |
| 覆盖主题 | 8 个 |
| 独立审核者 | 1 个 Human Proxy |
| 记录的审核时间 | 全部为 0 |
| 候选规则 | 4 条 |
| 可安全启用规则 | 0 条 |

旧数据不能证明多个人类审核者具有一致意见、规则能迁移到新主题、审核时间真的减少，或者自动放行不会产生新错误。

### 7.2 新实验直接比较“简单记忆”和“审核编译”

| 条件 | 含义 |
|---|---|
| `always_review` | 所有项目都由人审核 |
| `static_risk` | 使用固定风险规则选择审核项目 |
| `raw_memory_prompt` | 将历史审核记录直接加入 prompt |
| `review_compiler_active` | 使用经过验证的规则、依赖传播和主动审核 |

这个实验直接回答：Review Compiler 是否真的比“保存记录并放进上下文”更有效？

### 7.3 审核单位改为细粒度对象

审核者不再直接修改整篇文章，而是审核：

- 单个 claim；
- 支持它的 evidence path；
- 使用的 graph operator；
- 局部图视图；
- 系统给出的替代解释和置信度。

审核动作包括 accept、rewrite、reject evidence、reject operator 和 abstain。

这样才能知道错误究竟来自证据、计算还是文字解释，并观察一次反馈如何传播到全文。

### 7.4 人类审核实验测量什么？

| 指标 | 含义 |
|---|---|
| Correction Lag | 一次反馈后，还要出现多少个相似错误才能稳定改正 |
| Post-feedback Accuracy | 反馈后，相似问题上的准确率 |
| Rule Transfer Precision | 规则迁移到新主题后有多少是正确的 |
| Unrelated Regression | 修复一种错误时，是否破坏无关内容 |
| Unsafe Auto-accept | 系统自动放行了多少错误内容 |
| Review Seconds | 真实审核时间 |
| Corrections per Minute | 每分钟实际纠正多少错误 |
| Reviewer Agreement | 两名审核者的一致程度 |

成功标准不是单纯减少审核请求，而是：

> 在最终质量不低于全量审核的前提下，显著减少真实审核时间，同时不增加危险的自动放行。

## 8. 当前结果分别说明了什么？

### 8.1 已经比较清楚的发现

1. 旧任务确实太简单，只能证明 grounding 有用，不能证明图结构有用；
2. 复杂任务能够体现图计算优势；
3. 优势主要来自算子执行，仅检索相关子图不足以完成复杂计算；
4. 图格式没有独立优势，信息等价的 Graph Program 和 Flat Program 完全打平；
5. 现象卡能够增强图对全文的贡献；
6. 旧审核记忆缺少真实多审核者、时间记录、迁移验证和安全验证。

### 8.2 当前仍然只是研究假设

1. Graph Program 的优势是否会随图规模稳定增加；
2. 面对 dense、hybrid 或 RAPTOR 类强文本 RAG 时是否仍然领先；
3. 原始图和 provenance 是否能帮助模型识别错误算子输出；
4. Review Compiler 是否真的减少真实人类审核时间；
5. 规则是否能跨主题和跨审核者迁移；
6. 多现象文章是否会得到领域专家的稳定偏好。

## 9. 正式论文实验应该怎么完成？

### 9.1 Graph Program 正式实验

建议至少包含：

- 2 个开发主题；
- 2 个审核或规则校准主题；
- 8 个完全锁定测试主题；
- Small、Medium、Large 三档图规模；
- C1–C5 五档任务复杂度；
- 普通文本 RAG、普通图检索、Oracle、Operator Only、Flat Program 等完整消融。

主要检验：

1. Graph Program 在 C3–C5 上是否优于强文本 RAG；
2. Graph Program 在 C4–C5 上是否优于普通图检索；
3. 图优势是否随规模增加；
4. C1 上是否没有明显优势；
5. 在相同 token 预算下是否仍然成立。

### 9.2 人类审核正式实验

需要：

- 至少两名真实独立审核者；
- 双盲任务包；
- 审核分歧裁决；
- 完整审核时间记录；
- 规则形成主题与规则验证主题严格分离；
- Always、Static、Raw Memory、Review Compiler 四组比较。

正式结果必须同时报告质量、时间、安全性和审核者一致性。

### 9.3 文章质量正式实验

需要在多个锁定主题上比较旧机器稿、PhenomenonCard v2 稿和已发表人类参考稿。

领域专家重点评价：

- 图派生洞见；
- 复杂现象；
- 跨证据综合；
- 领域具体性；
- 论证深度；
- 过度推断；
- 整体研究价值。

---

## 10. 论文最终可以形成的两个主要创新点

### 创新点一：Graph Program RAG

在大规模文献计量图上执行多跳、社区、反事实、时间和跨网络计算，并把计算结果与原始证据一起提供给模型。

创新不在“图格式”，而在问题分解、可执行图算子、连通证据检索、反事实检查、provenance 回链，以及从结构计算到文章论证的完整链条。

### 创新点二：Human Review Compiler

把人类反馈编译成有适用条件的规则，并通过跨主题迁移、无关任务回归和依赖传播验证其可靠性。

创新不在“保留审核历史”，而在细粒度错误定位、规则编译、依赖传播、迁移验证、回归测试和成本敏感的主动审核。

---

## 11. 一句话总结

> 本轮工作把图的作用从“提供额外资料”升级为“执行复杂结构计算”，把人类审核从“保存历史意见”升级为“生成经过验证的可执行规则”；当前 pilot 已经显示图程序明显优于普通检索，但规模效应、人类成本降低和文章专家质量仍需要正式实验验证。
