# IP&M 同类论文写法对照与本稿调整

核对日期：2026-08-27。

## 1. 阅读范围与结论

本次对照三篇与计算型文献综述、学术评价或人机知识处理有关的 IP&M 论文，依据是 ScienceDirect 出版社页面提供的引言、引言末尾的章节安排及部分正文预览。**没有取得三篇全文，不能称为全文精读；PaperEval 返回的引言片段还存在中间省略，不能据此重建所有段落。** 以下“结构”是根据作者的章节说明概括的内容顺序，不冒充逐字目录。

现行作者指南仍未成功读取。已发表论文的写法可为本稿提供参考，但不等于现行投稿规范。原八节结构是编辑选择，并非期刊规定的八节模板。

### 引言的推进方式

**Chung 等：** 从领域趋势分析的需求切入，承认既有计算方法的作用，再指出数据、领域语义和前瞻分析方面的限制，随后提出目标、方法与案例。值得借鉴的是问题与方法的对应，而不是复用其具体缺口。

**PaperEval：** 从论文评价的重要性与人工评审的困难切入，再引入语言模型及多智能体方法，说明方法变体、评价数据与研究意义。可见内容把方法如何比较、服务于谁交代得较早；对缺失的引言段落不作推断。

**Wei 与 Chen：** 先界定知识构建及问答任务，再提出人机比较问题，连接评价理论、指标和实证设计。值得借鉴的是先解释“评价什么”，再说明“如何测量”；不能照搬它的理论或用文本质量代表人的真实理解。

以上为基于可见内容的写法分析，不是对论文全部结论的复核。

## 3. 对 CiteWeave 的具体调整

### 3.1. 引言围绕一个任务推进，减少并列技术介绍

我们的叙事应当是：

**研究者如何完成领域分析 → 哪些环节已经自动化 → 生成结构性判断还需要哪些证据 → 证据出错后如何一致修订 → CiteWeave 如何处理 → 如何验证。**

GraphRAG、程序执行和人工审核在这里承担解决问题的作用，不应分别写成三个互不相干的技术背景。引言介绍研究空缺时需要一例贯穿全文：例如“某主题是否连接了不同研究群体”，从数据、计算、解释一路连接到证据纠正。

### 3.2. 明确提出三个任务挑战，但不把它们写成未经证实的文献缺失

| 任务挑战 | 本系统的回应 | 对应评价 |
|---|---|---|
| 结构性判断需要明确的计算依据，相关片段不一定足以支持判断 | 预先登记的图操作与可检查的计算证据 | 简单查询与复杂结构任务的对照；计算、检索与信息供给的区分 |
| 计算结果到文字解释之间存在支持范围问题 | 关联计算、来源、声明及限制 | 声明支持、来源追溯与相同证据条件下的文章评价 |
| 上游证据纠正可能影响多个判断与段落 | 已记录依赖关系上的审核与受控修订 | 纠错质量、受影响内容识别、审核投入及留出验证 |

这些是本任务需要解决的问题。要写成“现有方法尚未解决”，仍需对最接近方法的全文、代码和实验逐项比较，不能只靠摘要或系统名称判断。

### 3.3. 贡献段用研究动作组织

中文 v0.2 将贡献集中为计算与解释的证据连接、依赖感知审核、分层评价设计三点。减少“我们不声称……”一类反复出现的写作提醒，但保留实际约束：预设任务程序、基准支持材料、图节点上限、未记录依赖，以及尚未完成的人工实验。

目前可以陈述框架机制与评价设计；不能把尚未观察到的效果写成“显著提高”“降低人工成本”或“优于现有方法”。

### 3.4. 目录保留弹性，不因样例篇数而机械增删章节

八节目录暂时可保留。第三节有独立价值的前提是，它确实说明任务、两类图和三个研究问题，而不是重复引言。若后续正文显得零散，可将任务定义并入方法，将研究问题放在引言末尾，形成七节结构：

1. 引言
2. 相关工作
3. 方法框架（含任务定义）
4. 评价设计
5. 结果
6. 讨论
7. 结论

这个合并是篇章组织选择，不是“期刊要求七节”。本轮没有擅自重排已有稿件，方便先对论证主线作出决定。
