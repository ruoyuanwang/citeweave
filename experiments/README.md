# CiteWeave Experimental Program

This directory is the authoritative record for the English-language experiments
reported for CiteWeave. Experimental claims are valid only when they can be
traced to a registered dataset snapshot, a versioned protocol, machine-readable
run outputs, and an analysis entry in `STATUS.md`.

## Files

- `PLAN.md` — maintained experimental plan, hypotheses, stages, and acceptance gates.
- `BENCHMARK.md` — benchmark tasks, metrics, scoring rules, and statistical tests.
- `datasets.yml` — registered acquisition protocols and snapshot requirements.
- `STATUS.md` — current execution state, decisions, deviations, and verified results.
- `PAPER_ROADMAP.md` — defensible claims, remaining publication work, and journal strategy.
- `runs/` — machine-readable experiment outputs. Large project packages remain ignored.
- `reviews/` — human-review decisions and feedback-memory artifacts.

## Versioned datasets

The eight immutable formal OpenAlex source snapshots are stored at
`formal_workspaces/<dataset_id>/staged/source_records.jsonl.gz` and tracked with
Git LFS. Install Git LFS before cloning or run `git lfs pull` after cloning.
Their registered queries, date ranges, roles, and acquisition settings are in
`formal_datasets_openalex_title_abstract.yml`; completion and hash checks are in
`formal_completion_audit_current.json` and the per-run manifests.

Only the compressed source snapshots are versioned from each formal workspace.
Canonical Parquet tables, evidence bundles, figures, and other derived workspace
artifacts are regenerated by the processing and experiment scripts and are not
duplicated in Git history.

## Reproducibility rule

Every reported result must record:

1. dataset identifier and immutable snapshot hashes;
2. source, query, date range, retrieval time, and truncation status;
3. Git commit and dirty-worktree status;
4. model/provider/version, prompt version, temperature, and seed where applicable;
5. raw predictions, gold answers, per-item scores, and aggregate metrics;
6. human decisions, reviewer identity code, reason, and elapsed review time;
7. failed and excluded runs with an explicit reason.

The experiments use English queries, prompts, answers, annotations, and reports.

## Reproduction commands

```powershell
.\.venv\Scripts\python.exe scripts\acquire_experiment_datasets.py --all
.\.venv\Scripts\python.exe scripts\run_experiment_benchmarks.py --dataset rag_graph_2022_2025
.\.venv\Scripts\python.exe scripts\run_adaptive_review.py
.\.venv\Scripts\python.exe scripts\evaluate_adaptive_review.py
```

The LLM ablation runner supports `no_graph`, `figure_vlm`, and `graph_rag`
conditions. The completed local experiment used the matched text-only
`no_graph` and `graph_rag` conditions. The figure/VLM condition remains
unexecuted and must not be treated as evidence.

```powershell
.\.venv\Scripts\python.exe scripts\run_llm_graph_ablation.py `
  --dataset climate_adaptation_2018_2020 `
  --condition graph_rag `
  --model qwen2.5-1.5b-q4km `
  --base-url http://127.0.0.1:8091/v1 `
  --api-key-env LOCAL_LLM_KEY `
  --workers 2 `
  --max-tokens 384
```

Saved raw responses can be rescored after a scorer correction without calling
the model again:

```powershell
.\.venv\Scripts\python.exe scripts\rescore_llm_runs.py `
  --dataset crispr_editing_2018_2020 `
  --dataset quantum_machine_learning_2019_2021 `
  --dataset climate_adaptation_2018_2020 `
  --model qwen2.5-1.5b-q4km

.\.venv\Scripts\python.exe scripts\analyze_pooled_llm_ablation.py `
  --model qwen2.5-1.5b-q4km
```
