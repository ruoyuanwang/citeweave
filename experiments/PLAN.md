# CiteWeave 正式实验计划

**协议版本：** 0.5  
**状态：** 按“同主题、独立检索、全量采集”原则重构，等待正式 API 配置  
**系统输出语言：** 英文  
**实验说明语言：** 不作限制  

## 1. 总体目标

正式实验先选择高质量真人文献计量论文，以其研究主题作为任务定义。CiteWeave 不复用真人论文的检索式或数据，而是根据主题独立生成检索式、独立选择合法可访问的数据源、抓取完整年份范围内的全量匹配记录，并独立完成分析和英文报告。

实验回答三个问题：

1. CiteWeave 能否基于完整年份数据生成接近已发表真人文献计量工作的报告？
2. 反馈驱动的自适应审核能否在最终质量不下降时减少外部 Judge 请求？
3. Graph RAG 能否比无图谱、扁平结构化上下文和 Figure/VLM 产生更可靠的网络解释？

当前 172–300 篇的四个数据集只保留为代码开发和流程测试数据，不进入正式论文主结果。

## 2. “全量数据”的操作性定义

“全量”不是指数据库中的全部学术文献，而是指：

> 对 CiteWeave 独立生成并冻结的数据源、检索式、文献类型、语言规则和完整年份区间，获取该数据源返回的全部匹配记录，不设置 `max_records` 截断。

正式数据必须满足：

- 年份区间使用完整自然年，例如 2015-01-01 至 2024-12-31；
- 获取过程持续到 API 结束游标、最后一页或数据库声明的结束条件；
- `failed_pages = 0`；
- 不允许以 Top-K、相关度排序前 N 条代替全量结果；
- 保存数据源声明总数、实际收到数、去重后数量和数量差异；
- 保存原始分页响应、检索时间、检索式、版本信息和 SHA-256；
- 真人论文的文献数仅作为背景，不要求与 CiteWeave 的独立检索结果一致；
- 正式结果必须明确是“该检索协议下的完整快照”，不能称为该领域的绝对完整集合。

### 数据来源原则

- CiteWeave 优先使用能够程序化完整分页的开放或已授权数据源；
- 人类论文使用何种数据库不限制入选，因为它只提供同主题的人类成果参考；
- CiteWeave 的检索式由系统根据主题、研究问题和关键词独立生成；
- 检索式在开发主题上调试后冻结，锁定主题不得根据结果数量反向修改；
- 若单一来源不能提供完整分页或关键引用字段，应在采集前更换来源或明确采用多源合并协议；
- 不使用真人论文的文献集合训练查询生成器，也不以“接近真人论文文献数”为优化目标。

## 3. WP0：先选择真人参考主题，再锁定任务

### 3.1 目标数量

- 2 篇开发论文：用于调试数据转换、生成 Prompt 和 Judge 量表；
- 4–6 篇锁定论文：用于正式确认性实验；
- 每篇论文对应一个研究领域和一套完整数据快照。

开发论文不得进入确认性汇总。

### 3.2 入选标准

候选论文必须：

- 是正式发表的英文文献计量研究；
- 具有清晰、可独立定义的研究主题；
- 给出完整年份范围，或允许我们预注册一个覆盖相同历史阶段的完整年份范围；
- 分析方法与 CiteWeave 当前能力有足够交集；
- 至少包含年度趋势、来源/作者/机构统计及一种网络分析；
- 至少包含一段对网络、聚类或主题结构的真人解释；
- 图、表、结果和讨论正文能够用于内部盲评；
- 正文质量足以作为已发表人类成果参考。

### 3.3 排除标准

- 主题边界无法转换成独立检索任务；
- 只分析单一期刊、单一机构或单一作者，且不适合作为领域任务；
- 年份边界无法确定；
- 主要结论依赖全文人工编码而不是文献计量数据；
- 缺少可用于比较的实质性结果或讨论；
- 主题在合法可访问数据源中无法进行全量分页采集。

### 3.4 论文登记表

每篇入选论文记录：

- DOI、题目、期刊和年份；
- 研究领域；
- 论文原始年份范围；
- CiteWeave 正式采用的完整年份范围；
- CiteWeave 独立生成并冻结的检索式；
- CiteWeave 数据源、文献类型和语言规则；
- 预计记录数与最终全量记录数；
- 双方共有的分析项目；
- 可用于盲评的结果和讨论章节；
- 论文访问和内部评价限制。

在人类参考论文登记表冻结之前，不启动正式数据采集。

## 4. WP1：独立检索与完整数据获取

对每篇人类参考论文构建一个 CiteWeave 项目：

1. 从论文标题、摘要和研究问题抽取主题定义；
2. 由 CiteWeave 独立生成候选检索式；
3. 由 Query Judge 检查检索式是否覆盖主题概念且没有明显无关扩张；
4. 在看到正式结果前冻结检索式、数据源、文献类型和完整年份范围；
5. 不设记录上限，分页获取年份范围内全部匹配记录；
6. 转换为 CiteWeave 标准表并保留原始数据源标识符；
7. 完成系统支持的全部分析，而不是复制真人论文的分析步骤；
8. 生成独立的英文端到端报告。

### 对齐原则

- **必须相同：** 研究主题和大体历史阶段；
- **尽量相同：** 完整年份边界和主要文献计量任务；
- **不要求相同：** 检索式、数据库、文献集合、记录数和具体数值结果。

因此，人类论文不是 CiteWeave 数值结果的 Gold，也不是检索复现目标。它只代表同主题下已发表的人类分析成果。

## 5. WP2：端到端实验

### 5.1 条件

#### Condition A：Structured One-shot LLM

使用与完整系统相同的确定性上游结果：

- 语料统计；
- 年度趋势；
- Top 来源、作者、机构和关键词；
- 网络规模；
- Top 节点；
- 最强关系；
- 聚类摘要；
- 图表目录与说明；
- 方法参数。

这些结果由固定规则压缩成可放入上下文的 `Structured Analysis Package`，然后只调用一次 DeepSeek 生成完整英文报告。

不使用：

- Graph RAG；
- 分阶段生成；
- 证据路径约束；
- Feedback Judge；
- 错误后修订；
- 历史反馈记忆。

压缩过程必须是确定性程序，不得额外调用 LLM。

#### Condition B：CiteWeave Full

使用相同上游数据和分析结果，但启用：

- 分阶段报告生成；
- Graph RAG；
- 证据绑定；
- 问题检测；
- Feedback Judge；
- 修订流程；
- 自适应反馈记忆。

#### Condition C：Published Human Reference

使用同主题真人论文的结果和讨论部分作为人类参考。它不是同数据、同检索式或同成本的严格 baseline，而是同主题下的发表质量参考。

#### 分析层参考：Bibliometrix/VOSviewer

在可匹配参数的分析上与 Bibliometrix 或 VOSviewer 比较，验证底层文献计量结果。传统工具不参与自然语言报告质量排名。

### 5.2 主要指标

只保留：

1. **Unsupported Claim Rate（UCR）**：报告中不受冻结数据、图和证据支持的经验事实比例；
2. **Blind Report Preference**：Evaluation Judge 对匿名报告进行 A/B/平局比较；
3. **Human-reference Quality Gap**：CiteWeave 与真人参考在统一 1–5 综合质量量表上的差值；
4. 时间、Token 和 API 成本仅作为辅助结果。

### 5.3 主要比较

- CiteWeave Full vs Structured One-shot；
- CiteWeave Full vs Published Human Reference；
- Structured One-shot vs Published Human Reference。

由于双方数据和数值不同，不进行逐数值一致性比较。每份报告的事实可靠性分别依据其自身证据评价：CiteWeave 依据冻结数据、KG、表和图；真人论文依据论文自身的方法、表和图。双方只在相同主题任务下比较分析覆盖、解释质量、结构、谨慎性和整体有用性。盲评前去除作者、期刊、系统名称和明显可识别的排版特征，并控制比较文本长度。

## 6. WP3：反馈驱动的自适应审核实验

### 6.1 条件

- **Always Review：** 每个候选输出都调用 Feedback Judge；
- **Static Review：** 固定检测规则和固定阈值，不学习历史反馈；
- **Adaptive Review：** 使用历史 Judge 决策、修改原因、问题类型和上下文更新审核策略。

### 6.2 顺序设计

- 开发论文用于反馈积累；
- 随后进入按预注册顺序排列的锁定论文；
- 进入锁定阶段后冻结策略和阈值；
- 只有 Feedback Judge 的在线意见可以进入记忆；
- 最终 Evaluation Judge 的结果不得反馈给系统。

### 6.3 主要指标

只保留：

1. **Review Request Rate**：请求 Feedback Judge 的输出比例；
2. **Final Quality Pass Rate**：独立 Evaluation Judge 判为达到质量标准的最终输出比例；
3. **Unsafe Auto-accept Rate**：自动接受但被最终 Judge 判为不合格的比例。

主要结论要求 Adaptive Review 相比 Static Review 降低 Review Request Rate，同时相对 Always Review 的 Final Quality Pass Rate 满足非劣效。预注册非劣效界值为 3 个百分点。

论文表述限定为“在独立 LLM Judge 环境中减少外部审核请求”，不表述为已经减少真人专家劳动。

## 7. WP4：Graph RAG 实验

### 7.1 条件

1. **No RAG：** 只提供问题和最小背景；
2. **Flat Structured Context：** 提供与 Graph RAG 相同的事实，但序列化为扁平表格或 JSON；
3. **Figure/VLM：** 提供对应网络图、图例和问题；
4. **Graph RAG：** 提供问题相关的子图、节点、边、聚类、统计事实和证据关系。

Flat 和 Graph 条件必须包含相同实体、数值和关系，输入 Token 尽量匹配，以区分“图结构优势”和“获得更多信息”。

若同一视觉模型能够处理四个条件，四组统一使用该模型；否则模型差异必须单独报告，Figure/VLM 作为扩展比较而非严格因果比较。

### 7.2 问题

每篇锁定论文对应的数据至少生成：

- 结构化图事实问题；
- 局部邻域和路径问题；
- 跨社区桥接问题；
- 聚类和主题结构解释；
- 时间趋势解释；
- 错误前提和不可回答问题；
- 2–4 句自然语言解释问题。

建议每个领域 25–30 个问题。

### 7.3 主要指标

只保留：

1. **Unsupported Claim Rate**；
2. **Answer Completeness（1–5）**；
3. **Blind Pairwise Preference Win Rate**。

结构化准确率、证据 ID 正确率、JSON 合法率和拒答准确率作为补充材料指标。

### 7.4 主要比较

- Graph RAG vs No RAG；
- Graph RAG vs Flat Structured Context；
- Graph RAG vs Figure/VLM。

Graph vs Flat 是判断图结构本身是否有价值的关键比较。

## 8. WP5：LLM-as-Judge 协议

文本生成模型使用 `deepseek-v4-pro`，评价模型使用与其独立的 Codex 子代理，不存在同模型自评。Figure/VLM 模型必须从 DeepSeek API 的实际模型列表或另行配置的 DeepSeek 系列视觉接口中确认，不得在协议中假设一个不存在的模型 ID。

### 8.1 角色隔离

- **Generator：** DeepSeek；
- **Feedback Judge：** 无历史上下文的 Codex 子代理，参与在线审核；
- **Evaluation Judge A/B：** 两个新建、互不共享上下文的 Codex 子代理，只进行实验后盲评；
- **Adjudication Judge：** 只处理 A/B 冲突。

### 8.2 盲化

Evaluation Judge 只看到：

- 问题或报告任务；
- 匿名候选输出；
- 与该候选输出对应的证据包。CiteWeave 输出使用冻结数据和 KG 证据；真人论文使用其自身方法、表格和图形作为证据。

它看不到：

- 条件名称；
- DeepSeek Prompt；
- 检索日志；
- 是否经过在线审核；
- Feedback Judge 的历史意见；
- 人类论文的作者和期刊身份。

候选顺序随机化，并进行 A/B 顺序反转复测。

### 8.3 Judge 校准

使用程序构造的已知错误：

- 数值替换；
- 实体替换；
- 关系方向颠倒；
- 无证据因果解释；
- 正确释义；
- 正确和错误拒答。

Judge Prompt 在开发论文上校准后冻结。校准准确率、A/B Judge 一致率和重复样本稳定性放入附录，不作为主要系统效果指标。

## 9. 统计计划

- 所有条件在同一领域、同一问题或同一报告章节上严格配对；
- 以人类参考论文/研究领域为聚类单位；
- 使用 cluster bootstrap 计算 95% CI；
- UCR 报告绝对差值及 95% CI；
- 盲评报告胜、平、负比例及 95% CI；
- 自适应审核使用质量非劣效检验；
- Graph RAG 的三项主要比较使用 Holm 校正；
- 同时报告逐领域结果，避免总体效果由单个领域驱动。

## 10. 执行顺序

1. 搜索并审核候选真人文献计量论文；
2. 以论文主题建立开发主题和锁定主题登记表；
3. 由 CiteWeave 独立生成查询，并由 Query Judge 检查主题覆盖；
4. 冻结每个主题的检索式、数据源、文献类型和完整年份范围；
5. 完善无上限分页、断点续传和快照校验；
6. 独立抓取每个主题在年份范围内的全量数据；
7. 在开发主题上调试数据转换和 Prompt；
8. 冻结 Structured Analysis Package 规则；
9. 冻结 Generator Prompt 和 Judge Prompt；
10. 一次性生成所有锁定条件输出并落盘；
11. 匿名化、随机化后启动 Evaluation Judge；
12. 运行统计分析并生成结果表、图和英文系统报告。

## 11. 用户需要提供的内容

- DeepSeek API 的配置位置、模型名称和允许预算；
- 若执行严格 Figure/VLM 对照，提供可用视觉模型接口；
- 若 CiteWeave 选择的数据源需要授权，提供相应合法访问权限。

用户不需要进行人工标注。真人论文承担“已发表人类成果参考”，Codex 子代理承担统一盲评。

## 12. 主要交付物

- 人类参考主题、独立检索式和数据源登记表；
- 每个领域的完整数据快照及采集证明；
- Structured One-shot、CiteWeave Full 和人类参考的匿名比较包；
- No RAG、Flat、Figure/VLM 和 Graph RAG 输出；
- Feedback Judge、Evaluation Judge 和裁决日志；
- 主结果表、置信区间和统计检验；
- 英文端到端系统报告；
- 失败、排除、检索漂移和协议偏差记录。
